# Strict Contracts & Validation Skill for MIND

This skill guides all AI agents and developers working on the MIND (Molecular INtelligence through Domains) repository. Its goal is to prevent silent fallbacks, broken data contracts, and untested assumptions across multi-domain molecular pipelines (Protein, RNA, Small Molecules).

## 1. Core Principles

### Principle 1: Fail Loud (No Silent Fallbacks or Swallowed Exceptions)
- **Never silently return unmodified data** when a domain-specific transform or encoder module encounters a sample missing expected metadata.
- If a protein sample is missing `pos_code`, `block_idx`, or `edge_index`, raise an explicit, descriptive `ValueError` or `TypeError` containing the `mol_id` and dataset type.
- **Forbidden pattern:**
  ```python
  # BAD: Silently skips logic and hides bugs for months
  if not hasattr(data, "expected_field"):
      return data
  ```
- **Mandatory pattern:**
  ```python
  # GOOD: Identifies domain and fails loud on malformed inputs
  if dtype in ("protein", "pdb"):
      if not hasattr(data, "pos_code") or data.pos_code is None:
          raise ValueError(
              f"Protein sample missing 'pos_code' contract: mol_id={getattr(data, 'mol_id', '?')}"
          )
  ```
- Never use bare `except:` or `except Exception: pass` to silence tensor shape mismatches, missing keys, or attribute errors during training steps or metric calculations.

---

### Principle 2: Test Against Production Contracts (No Made-Up Mocks)
- All unit tests in `tests/test_*.py` must adhere strictly to the actual fields generated by `cache_to_pyg.py` and `LazyUniversalDataset`:
  - **Protein / RNA:** `pos_code` (list/tuple of atom position strings, e.g. `'CA'`, `'CB'`, `'N'`), `block_idx`, `z`, `pos`, `edge_index`, `dataset_type`.
  - **Do NOT invent synthetic mock fields** (e.g. `position_indices`) that do not exist in production `.pt` files.

---

### Principle 3: Multi-Domain Isolation & Passthrough Testing
Every new data transform, graph view builder, encoder feature, or loss function must have unit tests verifying three cases:
1. **Valid Domain Execution:** Correctly applies transformations to target domain samples (e.g. Protein CA-CA Tier-3 dynamic edges added).
2. **Safe Passthrough for Other Domains:** Non-target domains (e.g. UniMol, RNA) pass through cleanly without unintended modifications or errors.
3. **Fail-Loud Validation:** Malformed or incomplete target domain samples raise descriptive exceptions immediately.

---

### Principle 4: Objective Purity & Shortcut Prevention
- Never introduce auxiliary loss tasks (e.g. shortcut distance heads between masked slots and anchors) that can be solved trivially by memorizing slot marginals or constant geometry without understanding 3D chemical context.
- Validate any new objective with owner counterfactuals (removed vs shuffled owner context) before proceeding to large training runs.
